# TradeOps ERP 产品需求说明

## 1. 项目目标

建立面向数字商品交易业务的统一运营中台，减少售前、销售、运营、客服、风控和管理层之间的信息断点。系统需要把 AI 识别结果转为可执行任务，同时确保库存、金额和审批由确定性规则控制。

## 2. 角色与核心诉求

| 角色 | 当前痛点 | 目标能力 |
| --- | --- | --- |
| 销售 | AI 对话后的高意向用户容易丢失 | 线索、预算、下一步动作可跟进 |
| 运营 | 账号库存依赖表格，状态更新不及时 | 唯一库存锁定与订单履约联动 |
| 客服 | 售后需跨页面查订单、库存和历史记录 | 工单聚合上下文和 SOP |
| 风控/主管 | 高风险订单与退款缺少统一审批入口 | 规则拦截、人工决策、可审计 |
| 系统运营 | 第三方接口异常难以及时发现 | 集成成功率、积压与降级方案 |
| 管理层 | 无法判断系统是否改善流程 | 使用数据、瓶颈证据与改进建议 |

## 3. 范围

首期范围：需求中心、线索/客户、账号库存、订单履约、售后工单、风险审批、SOP、集成监控、培训运营和运营分析。

首期不做：真实支付、真实公司用户数据、财务总账、采购、复杂组织权限和移动端原生应用。

## 4. 优先级

### P0

- 库存只能由 `available` 原子迁移到 `reserved`。
- 高风险订单必须人工审批，审批前不得履约。
- 退款审批需要联动工单、订单和库存。
- 所有关键状态迁移必须写入审计事件。
- 公开演示只能修改合成数据。

### P1

- AI 导购线索进入客户池并保留跟进动作。
- 售后自动分类、SOP 推荐和回复草拟。
- 第三方集成状态、积压和降级方案可查看。
- 按模块输出使用情况和流程瓶颈建议。

### P2

- 企业 SSO 与细粒度 RBAC。
- 真实消息队列、告警平台和数据仓库。
- 配置化风险规则与灰度发布。

## 5. 非功能要求

- 幂等：订单和工单创建必须有唯一幂等键。
- 一致性：库存锁定与订单创建处于同一事务。
- 可追溯：审批、履约和退款动作记录操作人及时间。
- 可降级：AI 不可用时不阻断确定性交易流程。
- 可移植：本地 SQLite，部署 PostgreSQL。
- 安全：密钥通过环境变量注入，公开操作限制合成实体。

## 6. 版本计划

| 版本 | 目标 | 验收出口 |
| --- | --- | --- |
| R1.0 | 交易履约主链 | 库存、订单、售后、审批闭环通过自动化测试 |
| R1.1 | AI 与集成增强 | TunTunAgent 线索接入、风险规则验证、集成监控 |
| R1.2 | 运营优化 | 使用统计、培训记录、流程瓶颈周期复盘 |
